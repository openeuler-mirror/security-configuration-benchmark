### 2.6.3 确保全局加解密策略配置禁用不安全算法

**级别：** 要求

**检查方式：** Automated

**规则说明：**

为保障系统传输与存储的密码学安全性，必须对操作系统全局加解密策略（Crypto-Policies）进行严格收紧。系统全局加密策略不得包含已被业界淘汰、存在安全缺陷或弱密码学特性的算法及模式，具体包括：

- 禁用 SHA-1 哈希及签名支持。

- 禁用长度小于 128 位的消息认证码（MAC）算法。

- 禁用 SSH 服务中的 CBC（密码块链接）加密模式。

- 禁用 SSH 服务中的 ChaCha20-Poly1305 算法（如果CVE-2023-48795的问题已得到解决，可以使用）。

- 禁用 SSH 服务中的 EtM（Encrypt-then-MAC）模式。

**规则影响：**

- 安全风险：不禁用不安全算法时，攻击者可利用弱算法的已知漏洞进行攻击（如SHA-1碰撞、CBC模式填充攻击等）。
- 配置影响：禁用不安全算法可能导致部分旧客户端无法连接。

**检查方法：**

检查/etc/ssh/sshd_config中是否已禁用不安全算法，依次验证以下各项（以下命令均无输出表示合规）：

1. 检查SSH相关配置中是否包含SHA-1算法：

```bash
# grep -iE "^Ciphers|^MACs|^PubkeyAcceptedAlgorithms|^HostKeyAlgorithms|^CASignatureAlgorithms" /etc/ssh/sshd_config | grep -iE "sha1|sha-1"
```

返回应为空。

2. 检查SSH相关配置中是否包含弱MAC算法（MD5及96位截断算法）：

```bash
# grep -iE "^Ciphers|^MACs|^PubkeyAcceptedAlgorithms|^HostKeyAlgorithms|^CASignatureAlgorithms" /etc/ssh/sshd_config | grep -iE "md5|-96"
```

返回应为空。

3. 检查MACs行中是否包含弱MAC算法（MD5、SHA1、96位截断）：

```bash
# grep "^MACs" /etc/ssh/sshd_config | grep -iE "md5|sha1|-96"
```

返回应为空。

4. 检查Ciphers行中是否包含CBC加密模式：

```bash
# grep "^Ciphers" /etc/ssh/sshd_config | grep -i cbc
```

返回应为空。

5. 检查Ciphers行中是否包含ChaCha20-Poly1305算法：

```bash
# grep "^Ciphers" /etc/ssh/sshd_config | grep -i chacha20
```

返回应为空。

6. 检查MACs行中是否包含EtM（Encrypt-then-MAC）模式：

```bash
# grep "^MACs" /etc/ssh/sshd_config | grep -i etm
```

返回应为空。

**修复方法：**

编辑/etc/ssh/sshd_config文件，修改Ciphers和MACs配置行，移除不安全算法，重启sshd服务使配置生效。

1. 禁用CBC模式、ChaCha20-Poly1305算法，修改Ciphers行，仅保留安全的加密算法：

```bash
# vim /etc/ssh/sshd_config
Ciphers aes128-ctr,aes192-ctr,aes256-ctr,aes128-gcm@openssh.com,aes256-gcm@openssh.com
```

2. 禁用EtM模式及弱MAC算法（MD5、SHA1、96位截断），修改MACs行，仅保留安全的MAC算法：

```bash
# vim /etc/ssh/sshd_config
MACs hmac-sha2-512,hmac-sha2-256
```

3. 重启sshd服务使配置生效：

```bash
# systemctl restart sshd
```

注：如果CVE-2023-48795的问题已得到解决且符合本地安全策略，可保留ChaCha20-Poly1305和EtM算法。修改前请确保客户端支持剩余的加密算法，避免SSH连接中断。

**默认值：**

openEuler默认配置DEFAULT策略，未默认禁用全部不安全算法，需根据场景手动配置子策略。
