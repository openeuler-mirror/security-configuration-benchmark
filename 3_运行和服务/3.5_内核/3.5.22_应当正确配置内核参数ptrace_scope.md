### 3.5.22 应当正确配置内核参数ptrace_scope

**级别：** 建议

**检查方式：** Automated

**规则说明：**

ptrace是一种系统调用，提供了一个进程（跟踪者）观察和控制另一个进程（被跟踪者）执行的能力，可以检查和修改被跟踪者的内存和寄存器。如果一个进程被攻破，攻击者可以利用ptrace attach到其他运行中的进程（如Bash、SSH会话、GPG agent等），提取额外的凭证并持续扩大攻击范围。

Linux Kernel 3.4及更高版本支持通过kernel.yama.ptrace_scope参数限制ptrace功能，可选值如下：

0：进程可以将PTRACE_ATTACH传递给任何其他进程，只要它是可转储的（即没有转换uid，没有特权启动或没有调用prctl）。

1：进程如果要调用PTRACE_ATTACH，必须有预先的定义关系。默认情况下满足上述条件时，预定义的关系仅为子进程的关系。若要改变关系，子进程可以调用prctl调整这种关系。

2：只有具有CAP_SYS_PTRACE的进程通过PTRACE_ATTACH或通过子进程调用PTRACE_TRACEME才能使用ptrace。

3：任何进程都不能将ptrace与PTRACE_ATTACH一起使用，也不能通过PTRACE_TRACEME使用。

openEuler默认参数为1，用户可根据实际使用场景进行配置，建议配置值为1或2，不应配置为0。

**规则影响：**

- 安全风险：配置为0时，攻击者可利用ptrace恶意提权。
- 配置影响：配置为1时被攻破的进程不能attach到同用户的其他进程，root仍可使用ptrace；配置为2时只有CAP_SYS_PTRACE的进程才能使用ptrace，普通用户的调试功能（如gdb attach）会受限。

**检查方法：**

首先，检查当前系统内核参数的设置，执行以下命令并检查ptrace_scope参数的返回值是否为1或2。

```bash
# sysctl kernel.yama.ptrace_scope
kernel.yama.ptrace_scope = 1
```

其次，执行如下命令，如果返回值不为1或2，建议修改配置文件内容。如果返回值为空，表示系统使用默认配置（值为1）。

```bash
# grep "^kernel.yama.ptrace_scope" /etc/sysctl.conf /etc/sysctl.d/*
```

**修复方法：**

* 设置ptrace_scope的值，可使用如下命令临时设置，重启后恢复默认值：

    ```bash
    # sysctl -w kernel.yama.ptrace_scope=1
    ```
    或
    ```bash
    # sysctl -w kernel.yama.ptrace_scope=2
    ```

* 修改/etc/sysctl.conf文件，添加或修改配置，并执行# sysctl -p /etc/sysctl.conf，使其永久生效：

    ```bash
    kernel.yama.ptrace_scope=1
    ```
    或
    ```bash
    kernel.yama.ptrace_scope=2
    ```

**默认值：**

openEuler默认配置ptrace_scope为1。
